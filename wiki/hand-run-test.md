# Hand-run test: what finding connections by hand taught the design

**What it was:** agents read Robert's own agent sessions and repositories and looked for ideas that recur across projects. Three models from three providers then checked the result independently. The findings are private and kept outside this repo.

**Standing:** proposed. Robert has not yet judged the connections. Until they do, this shows that plausible connections can be found, not that they are new or useful.

## The main lessons

| Lesson | Why |
| --- | --- |
| The most valuable thing to surface is the person's own earlier attempts at the same idea. | All three council members ranked this at or near the top. A person who starts many projects restarts ideas without seeing it. |
| Record why an attempt stopped. | Nothing records it today, and it is the most useful input to the next attempt. |
| The person maintains nothing. | Records the person must keep or read get deleted. Records agents keep and read are welcome. |
| Keep "what holds now" apart from "how we got here". | History shown as current truth is the confusion that makes people delete records. |
| Every stored item needs to say who wrote it. | About half the material was written by agents on the person's behalf. Without this the store reflects the tools back as the person's beliefs. |
| A proposed connection needs evidence a program can check. | Plausible, empty connections are the core failure. A connection should quote the person twice, from unrelated projects, with dates. |
| "Related" is not a kind of link. | Generic links did no work. |

## What has to be stored

| Unit | What travels with it |
| --- | --- |
| Utterance | Exact text, time, workspace, and who wrote it: typed, dictated, written by an agent, injected by a tool |
| Attempt | A project, repository or session with a life: started, how far it got, stopped, why |
| Decision or change of mind | From, to, cause, and whether it still holds |
| Mechanism | An idea restated without its project's vocabulary, so the same idea elsewhere gets the same description |
| Stance | A stated value or frustration, with a date |
| Connection | Kind, evidence, confidence, and the person's verdict |

## Kinds of link that did work

Same mechanism in unrelated domains. One project could solve another's problem. Contradiction between a stated position and a later action. Supersedes. Repeated attempt of. Triggered by.

## Operations that found the connections

| Operation | What it did |
| --- | --- |
| Restate each idea as a mechanism | Gave unrelated projects a common key to join on |
| Line up timestamps across workspaces | Showed two threads working on the same question at the same hour |
| Compare stated positions with later actions | Found contradictions |
| Match one project's output to another's bottleneck | Found "this could solve that" |
| Group projects into families and order by date | Found repeated attempts |
| Filter by who wrote it | Separated the person's thinking from agent text |
| Check each quote against the source | Kept the readers honest |

Topic similarity alone would have missed most of these. The best connections shared no vocabulary.

## How it could be judged

| Test | Question |
| --- | --- |
| Replay | Fed history up to a date, does it surface the earlier attempts the person confirms when a "new" project starts? |
| Precision | What share of proposed connections does the person rate "did not see this, and it changes my next step"? Include false connections on purpose to measure it. |
| Return use | Does the person consult it unprompted before starting something? |
| No filing | Does it stay current for two months from sessions and repositories alone? |

## North star wordings the council proposed

- Nothing the person starts is started from zero. Every new idea arrives already joined to what they have thought, built and abandoned before, with evidence they can check in a minute.
- A shared, evidence-bearing understanding across projects that reveals useful transfers and conflicts while keeping the person able to understand and steer.
- One agent-maintained memory of episodes, decisions and mechanisms that surfaces hidden links, contradictions and prior attempts before effort is duplicated or lost.

## The case against, as the council put it

- **Thin window.** Seventeen days of sessions. "Recurs across projects" may mean "recurs in one busy fortnight".
- **Echo.** Some recurring habits come from the person's tool setup and installed skills, and would fit any heavy user of coding agents.
- **Abstraction inflation.** Restated abstractly enough, everything connects.
- **Scope.** All three members warned, independently, that turning a daily tool into engine research before it is in daily use is itself the pattern that ended earlier attempts. All three recommended running a simple version daily on ordinary storage now and doing the engine research on its real data.
